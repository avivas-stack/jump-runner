# אמינות

כלי לבדיקת טענות, כותרות, ציטוטים, שמועות **וצילומי מסך** מול מקורות אמיתיים ברשת — בעברית, עם תמיכת RTL מלאה, Mobile-first.

**Phase 1 + Phase 2 הושלמו** (ראו "מה עוד חסר" למטה). הכלי הוא עזר לחשיבה ביקורתית, לא פוסק עליון — כל מסקנה מוצגת כ"בהתבסס על המקורות שנמצאו נכון לתאריך הבדיקה".

## ארכיטקטורה

Next.js 16 (App Router) + TypeScript, עם Tailwind CSS לעיצוב. כל הלוגיקה העסקית בצד שרת בלבד (`src/lib`), כדי שמפתחות ה-API לעולם לא ייחשפו ללקוח.

```
src/
  lib/
    types.ts            סכמות Zod + טיפוסי TypeScript לכל האובייקטים (טענה, ראיה, הערכה, דוח)
    config.ts            קריאת משתני סביבה עם ברירות מחדל וולידציה
    ssrfGuard.ts          הגנת SSRF: רזולוציית DNS מאומתת, חסימת טווחי IP פנימיים, הפניות מבוקרות
    pageRetrieval.ts      אחזור טקסט קריא מדף (cheerio), דרך ssrfGuard בלבד
    anthropic.ts          עטיפת קריאות ל-Claude עם פלט מובנה (tool-use) ואימות Zod — תומך גם בתוכן תמונה
    claimExtraction.ts    חילוץ טענות עובדתיות מטקסט (מודל זול)
    imageExtraction.ts    תמלול (OCR) טקסט מתמונה/צילום מסך, עם שימור אי-ודאות לטקסט מטושטש/חתוך
    search/               הפשטת ספק חיפוש (SearchProvider) + מימוש Tavily
    evidenceRegistry.ts   מרשם ראיות עם מזהים יציבים — ה-LLM יכול לצטט רק מזהה שכבר קיים
    evaluation.ts         הערכת טענה בודדת מול הראיות שנאספו לה (מודל חזק)
    report.ts             הרכבת הדוח הסופי + תקציר בעברית (ללא הוספת עובדות חדשות)
    pipeline.ts           האורקסטרציה: שלב → שלב, עם אירועי התקדמות אמיתיים
    rateLimit.ts          הגבלת קצב per-IP בזיכרון (תקציב נפרד לבדיקות טקסט ולהעלאת תמונה)
    reportStore.ts        שמירת דוחות ב-Supabase לצורך קישור שיתוף קבוע (best-effort, לא חוסם אם לא מוגדר)
    clientHistory.ts      היסטוריית בדיקות בצד הלקוח (localStorage), כולל קישור השיתוף של כל דוח
  app/
    page.tsx              עמוד הבית
    report/[id]/page.tsx   עמוד דוח משותף — נטען מ-Supabase לפי מזהה, עם Suspense לתוכן הדינמי
    api/verify/route.ts    מזרים (NDJSON) שלבי התקדמות אמיתיים ואז את הדוח; שומר אותו לשיתוף אם מוגדר
    api/extract-image/route.ts   תמלול תמונה בלבד — לא שומר את התמונה בשום מקום
  components/              רכיבי UI (טופס קלט + העלאת תמונה, שלבי טעינה, תצוגת דוח + השוואת טענות, היסטוריה)

supabase/migrations/        סכימת ה-DB (טבלת reports + מדיניות RLS) כקובץ SQL לשחזור בפרויקט Supabase חדש
```

### זרימת בקשה

1. הלקוח שולח `POST /api/verify` עם `{ text? , url? }`. אם המשתמש העלה צילום מסך, הטקסט תומלל קודם דרך `POST /api/extract-image` ומוצג לעריכה/אישור — רק לאחר מכן הוא נשלח ל-`/api/verify` כטקסט רגיל.
2. אם סופק קישור — נשלף תוכן הדף **דרך שומר ה-SSRF** (`ssrfGuard.ts`), לעולם לא פנייה ישירה.
3. חילוץ טענות עובדתיות מהטקסט המשולב (Claude, מודל זול).
4. לכל טענה: חיפוש אמיתי ברשת (Tavily), אחזור הראיה המובילה במלואה, רישום במרשם ראיות עם מזהה יציב.
5. הערכת כל טענה מול הראיות שנאספו **לה בלבד** — ה-LLM יכול לצטט רק מזהי ראיות אמיתיים; כל מזהה מומצא מסונן אוטומטית (קוד, לא רק פרומפט).
6. הרכבת דוח סופי + תקציר בעברית, שאסור לו להוסיף עובדה שלא כבר קיימת בהערכות.
7. אם Supabase מוגדר — הדוח נשמר (best-effort) תחת מזהה הדוח עצמו, וקישור שיתוף (`/report/<id>`) מוחזר ללקוח.
8. כל שלב משודר ללקוח בזמן אמת (NDJSON) ברגע שהוא **באמת מתחיל** — אין אחוזי התקדמות מבוימים.

## משתני סביבה

ראו `.env.example`. ההכרחיים/מומלצים:

| משתנה | הכרחי? | מה קורה בלעדיו |
|---|---|---|
| `ANTHROPIC_API_KEY` | כן | הבדיקה נכשלת עם שגיאה ברורה — אין אפשרות לחלץ/להעריך טענות או לתמלל תמונות בלי LLM |
| `ANTHROPIC_WORKSPACE_ID` | לפעמים | רק אם המפתח "משויך למשתמש" ולא ל-Workspace — ה-API עצמו אומר זאת במפורש בשגיאה |
| `TAVILY_API_KEY` | מומלץ מאוד | הבדיקה עדיין רצה, אך **מסומנת כ"בדיקה חלקית"** וכל טענה מסווגת כ"לא ניתן לאימות" |
| `SUPABASE_URL` / `SUPABASE_ANON_KEY` | אופציונלי (Phase 2) | בלעדיהם, הבדיקה עדיין עובדת במלואה — רק אין קישור שיתוף קבוע לדוח |

שאר המשתנים (`MAX_SEARCHES_PER_ANALYSIS`, `MAX_IMAGE_BYTES` וכו') הם כוונון עלות/ביצועים עם ברירות מחדל סבירות.

## ספק חיפוש

ברירת המחדל היא **Tavily** (`src/lib/search/tavily.ts`) — API יחיד, פשוט, מחזיר JSON נקי עם כותרת/קישור/תוכן/תאריך פרסום, ומתאים לשאילתות מחקר ממוקדות. קבלת מפתח: https://app.tavily.com

הקוד בנוי מאחורי הפשטה (`SearchProvider` ב-`src/lib/search/types.ts`), כך שניתן להוסיף בעתיד Brave Search API או את כלי החיפוש המובנה של Anthropic (`web_search`) בלי לגעת בשאר הפייפליין — אלה לא מומשו כדי להימנע מ"אינטגרציה מדומה": רק Tavily מחובר בפועל.

## אחסון דוחות ושיתוף (Phase 2)

Supabase פרויקט חינמי (`public.reports`: `id uuid primary key`, `report jsonb`) — כל דוח נשמר תחת המזהה (UUID) שהוא כבר מקבל בפייפליין, בלי טבלת משתמשים ובלי התחברות. ה-RLS מופעל עם **רק** שתי מדיניות: `insert` ו-`select` עבור תפקיד `anon` — אין מדיניות `update`/`delete` בכלל, כלומר הן **חסומות כברירת מחדל** גם אם מפתח ה-`anon` ייחשף (נבדק חי: ראו טבלת האבטחה). קישור השיתוף הוא `/report/<id>` — ציבורי ללא התחברות, בכוונה (דומה לקישורי שיתוף Google Docs); אם תרצה הגבלת גישה בעתיד, יש להוסיף שכבת הרשאות.

להקמה מאפס: `supabase/migrations/20261015000000_create_reports.sql` מכיל את כל הסכימה.

## אבטחה — מה יושם

- **SSRF**: כל כתובת (קלט משתמש או תוצאת חיפוש) עוברת דרך `ssrfGuard.ts` — פרוטוקול מוגבל ל-http/https, רזולוציית DNS מבוקרת עם בדיקת **כל** כתובת ה-IP שהוחזרה (לא רק שם המתחם) כנגד טווחי private/loopback/link-local/CGNAT/reserved, חיבור בפועל אל ה-IP שאומת (לא resolve נוסף אחריו — סוגר פער DNS-rebinding), מגבלת הפניות (עד 3), מגבלת גודל ו-timeout.
- **הזרקת פרומפט (Prompt Injection)**: כל תוכן חיצוני (טקסט שהוזן, תוכן דף, קטעי חיפוש, **וטקסט בתוך תמונה שהועלתה**) עטוף בתגיות `<content>`/`<evidence>` או בהנחיית מערכת מפורשת להתעלם מהוראות בתוכן; כהגנת עומק נוספת (לא תלויה רק בציות המודל), **כל מזהה ראיה שה-LLM מצטט נבדק בקוד מול המרשם** — מזהה שלא קיים נמחק אוטומטית לפני שהוא מגיע לדוח. טקסט שחולץ מתמונה מוצג תמיד למשתמש לעריכה/אישור **לפני** שהוא נכנס לפייפליין הבדיקה עצמו — המשתמש הוא שער הגנה נוסף.
- **XSS**: אין שימוש ב-`dangerouslySetInnerHTML` באף רכיב — React בורח (escapes) את כל הטקסט כברירת מחדל; קישורי מקורות הם `<a>` רגילים עם `rel="noopener noreferrer nofollow"`.
- **כותרות אבטחה**: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` מוגדרים גלובלית ב-`next.config.ts`.
- **הגבלת קצב ותקציב**: הגבלת בקשות per-IP לשעה **בנפרד** לבדיקת טענות (`rateLimit.ts`) ולהעלאת תמונה (תקציב נמוך יותר, כי קריאת vision יקרה יותר), תקציב חיפושים מוגדר לכל ניתוח, הגבלת גודל טקסט/קישור/תמונה בקלט (Zod + בדיקת בייטים מדויקת בשרת), timeout ומגבלת בייטים לכל אחזור דף. מפתח ההגבלה לוקח את ה-hop **האחרון** ב-`X-Forwarded-For` (לא הראשון, שהלקוח יכול לזייף).
- **העלאת תמונות**: סוגי קובץ מוגבלים ל-JPEG/PNG/GIF/WebP בלבד (לא SVG — מונע סיכון הטמעת סקריפט), מגבלת גודל נאכפת גם בצד הלקוח וגם בשרת (לא סומכים על בדיקת הלקוח), **התמונה מעולם לא נשמרת לדיסק או ל-DB** — מעובדת בזיכרון התהליך ונזרקת מיד אחרי הקריאה ל-Claude.
- **סודות**: מפתחות ה-API (כולל Supabase) נקראים אך ורק משרת (env vars), לעולם לא נשלחים ללקוח; `.env.example` ללא ערכים אמיתיים; `.env*` ב-`.gitignore`. ה-build נבדק שלא מכיל אף אחד מהמפתחות.
- **Supabase RLS**: מדיניות `insert`+`select` בלבד לתפקיד `anon`; `update`/`delete` חסומים כברירת מחדל (אין מדיניות = דחייה). נבדק חי מול ה-API (לא רק נקרא בקוד): ניסיון UPDATE/DELETE על שורה קיימת דרך מפתח ה-anon קיבל 200 עם תוצאה ריקה — כלומר לא שינה כלום.
- **אחסון**: אין שמירת טקסטים/תמונות גולמיים בצד השרת — רק דוחות סופיים, אופציונלי, ב-Supabase. היסטוריית בדיקות בצד הלקוח נשמרת רק בדפדפן המשתמש (`localStorage`).

ראו את דוח האבטחה המלא (כולל מה נבדק, מה נמצא, ומה עדיין פתוח) בהודעות שנשלחו אליך בצ'אט.

## שיפורים לאחר משוב משתמש (אחרי Phase 2)

- **סיכום פסקאי בנקודות**: `report.plainExplanation` הוא מערך של נקודות קצרות (לא פסקה רציפה), מוצג כרשימה.
- **תגית סיווג גדולה למעלה**: `VerdictHero` ב-`ReportView.tsx` — לטענה בודדת, תגית סיווג גדולה + הסבר ביטחון; למספר טענות, סיכום ספירה לכל סיווג. **לא** מצמצם ל"פייק/לא פייק" — שומר על כל שמונה הסיווגים, כי "לא ניתן לאימות" אינו "כנראה שקרי".
- **כפתור "בדיקה חדשה" גם למעלה**, לא רק בתחתית הדוח.
- **עדיפות למקורות ישראליים/עבריים**: שאילתת החיפוש הראשית לטענה בעברית נשלחת ל-Tavily עם `country: israel` ו-`language: hebrew` (boost, לא סינון קשיח — תואם לדרישה "עדיפות לעברית, תוך תמיכה באנגלית ובינלאומי"), ועם מיון נוסף בקוד שמעדיף תוצאות בעברית לאחיזת העמוד המלאה. **מגבלה**: זהו "boost" בלבד — Tavily עדיין עשוי להעדיף מקור אנגלי-ישראלי מוביל (כמו Jerusalem Post) כשהוא הכי רלוונטי; זה לא ערובה לתוצאות עבריות בלבד.
- **מקורות בדיקת עובדות נוספים**: irrelevant.org.il, fakereporter.net ו-special.n12.co.il (בחירות 2026) נוספו ל-`FACT_CHECKER_HOSTS` (`evidenceRegistry.ts`) — גם לסיווג סוג המקור וגם כ-boost בכל חיפוש (`include_domains` + `include_domains_mode: prefer`), בלי לצרוך חיפוש נוסף מהתקציב.
- **סימוכין מקוצרים**: קטע ראיה ארוך (מעל ~220 תווים) מוצג מקוצר עם כפתור "הצג עוד"/"הצג פחות" (`ExpandableExcerpt` ב-`ReportView.tsx`).
- **תיקון קריסה**: רשומות היסטוריה (`localStorage`) שנשמרו לפני שינוי בסכימה (למשל `plainExplanation` כמחרוזת במקום מערך) נבדקות מול הסכימה הנוכחית בטעינה ומוסרות בשקט אם אינן תואמות — לא מקריסות יותר את העמוד.
- **סיווג חדש: "ככה"נ שקרי"** (`evaluation.ts`) — נוסף לצד שמונת הסיווגים הקיימים, לא במקומם. משמש רק כששני התנאים מתקיימים יחד: (1) נאספו ראיות אמיתיות ואף אחת אינה תומכת בטענה, וגם (2) אין מקור מקורי/אירוע מתועד שתואם את הטענה בכלל, או שהראיות סותרות את ההקשר הבסיסי שלה. **לא** משמש רק כי הנושא צר/עדכני מדי — אז "לא ניתן לאימות" נשאר. ה-confidence מוגבל ל-medium לכל היותר, אלא אם יש גם סימן ברור לשמועה מומצאת. תג מקווקו (לא רציף) מבדיל אותו ויזואלית מ"שקרי" (הפרכה ישירה) ומ"לא ניתן לאימות" (חוסר מידע סתמי).
- **עיצוב עשיר יותר**: כותרת גדולה יותר עם סמל, שורת "איך זה עובד" (3 שלבים), וסיידבר בצד ימין (`Sidebar.tsx`) עם "פייק ויראלי" (כרטיסי טענות חיים מ-FakeReporter, עם קישור למקור וכפתור "בדוק את זה") ודוגמאות קבועות — נבדק ויזואלית שהסיידבר אכן בצד ימין ב-RTL (באמצעות `lg:order-1`/`lg:order-2` ב-flex, לא הסתמכות גרידא על סדר ה-DOM).
- **דוגמאות טענות דינמיות**: `src/lib/trendingExamples.ts` שולף מ-FakeReporter.net (דרך שומר ה-SSRF), ומודל זול בוחר אילו כותרות הן באמת טענה נבדקת (לא הודעת אתר/אירוע) ומנסח אותה כמשפט — מוצג עם ייחוס "(FakeReporter)". Cache בזיכרון ל-24 שעות; נופל חזרה לדוגמאות הסטטיות בכל כשל.
- **תיקון כללי בקוד**: מצב strict של Anthropic דוחה כמה מילות-מפתח של JSON Schema (`minimum`/`maximum`/`maxItems` וכו') ש-Zod מוסיף אוטומטית (למשל מ-`.int()` או `.max()`). `anthropic.ts` מסנן אותן באופן גורף לפני השליחה, כך שכל סכימה עתידית מוגנת מהבעיה הזו מראש.

## מגבלות ידועות

- **חיפוש אנגלית לטענות עבריות**: המודל מתבקש לייצר שאילתת חיפוש מתורגמת לכל טענה בעברית (`searchQueryEn`), אך זהו תרגום של עובדות-מפתח בלבד ולא מנגנון חיפוש רב-לשוני מלא.
- **הגבלת קצב בזיכרון בלבד**: `rateLimit.ts` עובד בזיכרון של תהליך שרת בודד. בפריסה עם כמה אינסטנסים (כולל ברירת המחדל של Vercel) המגבלה האפקטיבית גבוהה יותר מהמוגדר — לפרודקשן אמיתי יש להעביר למאגר משותף (Redis/Upstash).
- **ללא English UI**: Phase 3.
- **קישורי שיתוף ציבוריים לחלוטין**: מי שיש לו את הקישור (UUID לא ניתן לניחוש בפועל) יכול לצפות בדוח — אין בעלות/הרשאות משתמש.
- **נבדק מול מפתחות אמיתיים**: הורצו מבחני קבלה חיים (טענות אמת/שקר/לא-ודאי, תמונה אמיתית עם טקסט עברי, שמירה ושליפה אמיתית מ-Supabase) מול Anthropic, Tavily ו-Supabase אמיתיים. בתהליך נמצאו ותוקנו כמה פערים אמיתיים: `tool_choice` כפוי שנדחה על ידי מודלים עדכניים, הנחיית פרומפט שגויה שגרמה להחזרת רשימת טענות ריקה, וסכימת Zod לסיכום הדוח שלא איפשרה מערך ריק. כל הלוגיקה נבדקת גם באופן קבוע עם mocks דטרמיניסטיים (Vitest + Playwright) לבדיקות רגרסיה מהירות שאינן עולות כסף.

## בדיקות

`npm run test` מריץ 100 בדיקות יחידה/רכיב המכסות (עם mocks, ללא קריאות רשת אמיתיות): כל תשעת סיווגי הטענות (כולל "ככה\"נ שקרי"), פיצול טענה מרובה, תמלול תמונה כולל טקסט חלקית לא קריא, הגנת SSRF (IPv4/IPv6 פרטי, loopback, link-local, metadata endpoint, IPv4-mapped), ניקוי מזהי ציטוט מומצאים (הגנת הזרקת פרומפט), דף חסום/חלקי/לא נגיש, תקלת ספק חיפוש (רשת/401/429/5xx), הגבלת קצב (כולל זיהוי spoofed X-Forwarded-For), שמירה/שליפה מ-Supabase, סינון מילות-מפתח לא נתמכות בסכימת strict, דוגמאות טענות דינמיות, boost למקורות בדיקת עובדות, שחזור מקריסת היסטוריה ישנה, ותצוגת הדוח כולל מצב "בדיקה חלקית", תגית הסיווג הגדולה, השוואת טענות וקיצור סימוכין.

`npm run test:e2e` מריץ 4 תרחישים מול API מדומה: מסע המשתמש המלא (שליחת טענה → שלבי התקדמות אמיתיים → דוח עם מקורות לחיצים), העלאת תמונה עם אזהרת ביטחון נמוך, פריסת מובייל ללא גלילה אופקית, ומצב שגיאה ברור.
